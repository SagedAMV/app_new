# بناء النسخة المحدّثة 1.3.0

التاريخ: 2026-09-30. الحزمة: `com.unihub.app`، رقم الإصدار **4**.

## التحقق الفعلي

- نجحت ترجمة المصدر الحالي وتوليد Room وHilt.
- نجح 74 اختباراً دون فشل أو خطأ أو تخطٍّ، ومنها 3 اختبارات اتصال حي بـR2 ضمن مسار اختبار منفصل.
- نجح lintVital مع تحذيرات توافق داخل واجهة تحليل Kotlin.
- نجح تجميع releaseFull، وهي النسخة الكاملة غير المصغّرة.
- نجح فحص توقيع APK v2 وzipalign. شهادة APK تطابق شهادة مفتاح المشروع.
- قرأ aapt الإصدار 1.3.0 ورقم 4 وصلاحيات الشبكة والإشعارات من الحزمة نفسها.
- طابقت بصمات المصدر قبل البناء وبعده؛ لم يُستخدم APK قديم أو مصدر مختلف أثناء البناء.
- أُبقيت نسخة واحدة للتنزيل؛ المخرجات الثنائية المكررة حُذفت بعد التحقق. لم يُنفَّذ git push.

## مراجعة الاعتراضات

| الاعتراض | الدليل أو القيد |
|---|---|
| قد تكون الحزمة نسخة قديمة | رقم 4 واسم 1.3.0 من aapt، وبصمات المصدر قبل البناء وبعده |
| الاختبارات السابقة لا تكفي للبناء الحالي | إعادة تشغيل 74 اختباراً، مع صفر اختبارات متخطاة |
| وجود المفتاح لا يثبت صحة توقيع الحزمة | مقارنة SHA-256 للشهادة من JKS وشهادة APK، بالإضافة إلى apksigner verify |

الحل صامد ضد أقوى 3 هجمات: نعم، ضمن تحقق البناء والحزمة.

الهجوم الذي لم يُصَدّ بعد هو: اختبار الواجهة الجديدة على الهاتف الذي أظهر الدوران؛ وخطة مواجهته: تثبيت 1.3.0 دون حذف بيانات التطبيق ثم اختبار الفراغ والمهلة ورفع مجلد وتنزيل جزء منه.

## المخاطر المتبقية وخطة التحقق

1. سلوك الإشعار والواجهة على الهاتف: يمنح إذن الإشعارات ويُفتح زر السحابة.
2. حالة الشبكة أو أندرويد بالخلفية: يُفصل الإنترنت أثناء الفحص وتُراجع رسالة الخطأ/المهلة؛ الخلفية ليست Push لحظياً.
3. اختلاف توقيع نسخة مثبتة خارج مفتاح المشروع: إذا رفض التحديث، لا تُحذف بيانات التطبيق؛ تُرسل رسالة الرفض للفحص.

لا يمكن التحقق خارجياً | الثقة: متوسطة | السبب: لم يُشغَّل APK الجديد على هاتف فعلي في هذه البيئة.

## الاختبار المقترح

- تحقق من ظهور 1.3.0 في معلومات التطبيق.
- افتح السحابة الفارغة: يجب انتهاء المؤشر وظهور رسالة الفراغ.
- ارفع ملفين محددين فقط، ثم مجلداً فيه صور ومجلد فرعي.
- افتح المجلد في السحابة ونزّل صورة واحدة، ثم اختبرها دون إنترنت.
