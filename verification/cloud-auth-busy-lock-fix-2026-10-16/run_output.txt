== OLD behaviour (tryLock fail-fast) ==
  user upload       -> Fail(error=java.io.IOException: جارٍ تنفيذ عملية مصادقة أخرى)
  background pulse -> Ok(value=session-verified)
OLD: successes=0 failures=1 (upload wrongly rejected while unrelated background check was running)

== NEW behaviour (withLock queueing) ==
  background pulse -> Ok(value=session-verified)
  user upload       -> Ok(value=upload-authorized)
NEW: successes=1 failures=0 (upload now queues behind the background check and still succeeds)

VERIFIED: fix removes the 'جارٍ تنفيذ عملية مصادقة أخرى' spurious failure caused by lock contention.
